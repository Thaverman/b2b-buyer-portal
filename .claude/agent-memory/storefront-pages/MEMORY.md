# Storefront-Pages Memory

Cross-session learnings for the `storefront-pages` role. Add entries as you discover patterns, gotchas, or workflows worth preserving.

## Entries
- [Dropped tab-click race](pattern_dropped-tab-click-race.md) — collapsing tabs and dropping a now-redundant "click into tab" step can unmask a real render race between two independently-loaded queries; use `findByText`/`findAllByText` on the specific gated content, not a proxy assertion on unrelated always-visible text.
- [Negative-assertion race](pattern_negative-assertion-race.md) — a synchronous `queryByText(...).not.toBeInTheDocument()` right after an unrelated `await` can pass even when the guard it's meant to lock is deleted, if the "absent" content is gated behind a slower, independent `useQuery`; verified this empirically on Loyalty's PrePointsGate/`TierProgressCard` test.
- [Removed-section text used as anchor](pattern_removed-section-text-used-as-anchor.md) — a removal-sweep test brief can miss a test where the deleted component's string was reused elsewhere purely as a mount-order wait anchor, not as an assertion about that component; grep the whole page test suite for the removed component's strings before calling a sweep done.
- [Knip flags a type when its only consumer switches to a wrapper](pattern_knip-flags-type-when-consumer-switches-to-wrapper.md) — restructuring a flat shape into a nested one can leave an inner type used only inside its defining `api.ts`; knip calls that an unused export even though the type is still referenced. Drop `export` and use the file's existing "module-internal, knip fails on unused exports" comment idiom instead of assuming the brief's field addition implies the type must stay exported.
- [Index key must be precomputed outside the JSX-returning map](pattern_index-key-must-be-precomputed-outside-jsx-map.md) — `react/no-array-index-key` fires on `key={`${index}-${text}`}` written inline inside the same `.map((item, index) => <Jsx key={...}>)` call, even when an index-qualified key is the deliberately correct choice (repeat-safe theme/CMS text). Precompute `{ key, text }` in an earlier plain-data `.map()` (matching this codebase's existing `keyedSections`/`keyedItems` idiom) and reference `item.key` in the render map instead.
- [Asymmetric hop-count between two "independent" queries always resolves the same way](pattern_asymmetric-independent-query-hops.md) — when one gated query needs N sequential fetches before it's even `enabled` (e.g. identity → earned rewards) and a sibling query is one fetch fired on mount (e.g. cart), the single-fetch query deterministically wins the race every run — not flaky, not occasional. A test that awaits the fast query's content then synchronously asserts on the slow query's content will fail 100% of the time; wrap that assertion in `waitFor` instead of treating it as flakiness.
